# System Patterns: DevOps Hybrid Stand

## Архитектура гибридного цикла

```
┌─────────────────────────────────────────────────────────┐
│                    ГИБРИДНЫЙ ЦИКЛ                         │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────┐  │
│  │     Plan     │───▶│    Act       │───▶│ Verify   │  │
│  │ deepseek-v4  │◀──▶│  qwen3.5-9b  │◀──▶│ cloud/    │  │
│  │      (облако)│    │   (локально) │    │ локально  │  │
│  └──────────────┘    └──────────────┘    └──────────┘  │
└─────────────────────────────────────────────────────────┘

Слои инфраструктуры:
├─ 🌐 Сетевой слой: GNS3/EVE-NG/PNETLab
├─ 🖥 Серверный слой: KVM/libvirt
├─ ⚙️ Слой приложений: k3s/k3d
└─ 🔄 CI/CD-слой: Jenkins + Argo CD
```

## Компоненты и их роли
1. **Plan (deepseek-v4-flash)** — планирование, разбор ошибок, верификация планов
2. **Act (qwen3.5-9b-deep)** — исполнение кода, рутина, приватные задачи
3. **Fallback** — автоматический возврат в Plan mode при проблемах с Act

## Технические решения
### Memory Bank (6 файлов)
- `projectbrief.md` — цели и требования проекта
- `productContext.md` — контекст продукта и пользовательские сценарии
- `systemPatterns.md` — архитектура и паттерны проектирования
- `techContext.md` — стек, окружение, ограничения
- `activeContext.md` — текущий фокус работы
- `progress.md` — прогресс и статус задач

### Auto Compact + `/smol` + `/newtask`
Управление окном контекста через компакцию старых записей.

## Паттерны проектирования
1. **Plan/Act с разными моделями** — облачная для верификации, локальная для исполнения
2. **@-упоминания файлов** — точечная загрузка контекста из KB
3. **bounded retry** — ограниченные попытки выполнения с автоматическим возвратом
